# Model Price

Run the bundled script before answering. Keep the model-introduction section it returns: it states what the model is for, its main capabilities and specifications, any exceptional lifecycle state, and its official source. An active lifecycle is implicit and omitted from the message; preview, legacy, retired, and unknown states remain visible. The introduction opens the message before the conclusion and every price, because a reader needs the model's role and strengths to judge the available services and cost. Show every returned provider, version, service mode, region, price condition, official source, and source status — and when a price is split by time of day, the window it covers.

```bash
# Search domestic providers. GPT, Claude, or Gemini names also add their relevant first-party provider.
python3 scripts/query_model_prices.py compare MODEL --format message

# Query selected providers, require an exact ID, or include all overseas providers.
python3 scripts/query_model_prices.py compare MODEL --provider PROVIDER --provider PROVIDER
python3 scripts/query_model_prices.py compare MODEL --exact
python3 scripts/query_model_prices.py compare MODEL --include-overseas

# Query or list one provider.
python3 scripts/query_model_prices.py provider PROVIDER MODEL --format message
python3 scripts/query_model_prices.py list PROVIDER --prefix PREFIX

# Scan every catalogue and report what moved since the previous scan.
python3 scripts/query_model_prices.py delta --format message
python3 scripts/query_model_prices.py delta --provider PROVIDER --format json
```

Provider IDs: `aliyun`, `volcengine`, `tencent`, `baidu`, `deepseek`, `kimi`, `zhipu`, `minimax`, `xiaomi`, `openai`, `anthropic`, `google`, `xai`.

Pick the format by where the answer is going, not by preference: `--format message` whenever the result will be sent to a person over an instant messenger — DingTalk, WeChat, Feishu, or any other — and `--format json` otherwise. A request to send, forward, push, notify, or 「发给我」 over IM is a request for a message, so pass `--format message` for it without being asked to. `compare` and `provider` default to `json` because their usual consumer is another program; `delta` defaults to `message` because its usual consumer is a channel.

Two lengths are limited, and neither limit is met by cutting — go under it by summarizing, never by dropping.

A model introduction carries at most 300 characters. A vendor publishes an announcement rather than a summary (one DeepSeek page opens with a whole press release), so an introduction that runs past the limit is flagged `summary_needs_condensing` in the payload and its 用途 line carries a label naming its length and the limit instead of a plain one. Write that summary yourself before sending: at most 300 characters, the same meaning, the same 来源 line, and the label goes with the original it described. The vendor's words stay whole in `--format json`, because the tool cannot summarize — it takes no credentials and has no model to ask — and it will not cut, because a sentence that stops mid-clause reads as the vendor's complete wording.

A message carries at most `--max-chars` characters, 3000 by default, well inside the 5120 a DingTalk text message holds: the number of providers only grows, and one message has to stay one message. `compare`, `provider`, and `delta` all stop there. An over-long message is the whole report plus one closing line saying how far over it is and what the summary must keep. Summarize it yourself before sending, keeping the title, the conclusion, every channel with its model version, service mode and region, every billing condition, every amount with its unit, every peak/off-peak window, each channel's source page, and the status of every channel scanned — including the ones that failed. Condense the prose: the introductions, the sentences quoted from vendors, the differences summary, and the wording of each change. Never drop a channel, an amount, a condition, or a status to make the message fit, and never let a line end mid-amount.

Do not query `openai`, `anthropic`, `google`, or `xai` by default. Add only the relevant provider when the user explicitly mentions GPT/OpenAI, Claude/Anthropic, Gemini/Google, or Grok/xAI; use `--include-overseas` when the user explicitly asks about overseas models generally.

Each provider caches lists and price searches independently under `cache/`. Fresh caches are valid for 3 hours. Add `--refresh` only when the user asks for the latest/current refresh; with `provider` or repeated `--provider`, refresh only those providers. `delta` is the exception — it always reads the sources afresh, because a cache hit would hand the previous scan back as "no change".

Model introductions are model-level, not price-channel-level: one DeepSeek model compared across five hosts gets one first-party introduction rather than five near-duplicates. Introduction sources are independent from price adapters and cache under their own `description` operation. Prefer the model vendor's official source, then the hosting platform. A missing, retired, or old model is reported honestly as `not_found`; an unreadable introduction source is `source_error`, and neither status may suppress an otherwise valid price result. Tencent TokenHub uses the checked-in authenticated mirror under `descriptions/data/`; never infer text for a model absent from that mirror.

`delta` is the incremental run, for a scheduled or repeated check rather than a question about one model. It takes no model name: it scans each provider's whole catalogue and compares it with the baseline the previous run left in `snapshots/`. It covers domestic providers only unless `--include-overseas` is given, prints a DingTalk-ready message unless `--format json` is asked for, and runs the skill's own Git update check the way any refresh does. A baseline never expires, so a run a week later still compares against the last scan. A scan takes tens of seconds rather than a moment: Bailian's catalogue is paged, and consecutive pages wait a random 1–3 seconds so the walk stays under that gateway's rate limit.

Report every scanned provider, including the ones that did not move — that is what shows the scan actually covered them. A first run reports `baseline_created` and how many models it recorded, instead of claiming nothing changed. `unchanged` is stated plainly as 无变化. `changed` lists the models added with what they cost, the models withdrawn with what they cost before, the offers added or removed, and every price that moved, old amount to new. A provider that fails (`source_error`) or yields no priced model (`empty_scan`) is named with its reason and keeps its previous baseline rather than overwriting it, so the change stays visible once the source recovers.

In an expanded scan overview, omit the empty 本次变化 field for an unchanged provider. Show 官方更新时间 when the price source publishes one. Tencent, Baidu, and Xiaomi expose that stamp on their official pages; DeepSeek is checked for a matching official news URL in the most recent seven days. When a source publishes no stamp or DeepSeek has no recent news page, show 上次更新时间 from the previous successful snapshot. Never label a fallback scan time as an official vendor update.

For every model named in a `changed` provider's detail (new, removed, offer change, or price change), keep the 「变化模型能力」 block the scan opens with: it introduces each of those models once, at the top, before any channel's before-and-after, because what a model is for does not change with the channel that reported the movement. Only changed models are looked up during `delta`; unchanged catalogues must not trigger hundreds of detail-page requests.

The report is built to be skimmed before it is read, and it opens the same way a comparison does: the title 模型价格自动检测 with the scan time in local terms (`2026-09-16 13:37（UTC+8）`), then 变化模型能力 introducing the models this scan reports as moved. Below that come four levels: one line stating the scan — how many channels, how many models, how many moved, how many could not be read; an entry per channel with its model count, status, what moved, and the vendor's own update stamp, channels that moved first; and below that, the detail of only the channels that actually moved, closed by a line saying what the channel states add up to. The first screen must answer whether anything moved and how far the scan reached, and a channel that held still is a line in that list, never a section of its own.

A scan that read every channel and found none of them moved prints its title and its one-line conclusion and nothing else: a scheduled run still reports that it ran, without repeating the whole catalogue every day. Anything else — a channel that moved, a channel that could not be read, or a first run with nothing to compare against — keeps the full report, because there the detail is what the message is for.

Both outputs are plain-text messages, meant to be forwarded into a DingTalk channel as they stand rather than filed as a document. They carry no Markdown markup at all, because DingTalk reads a document back through its own parser and renders a report this dense wrongly. Hierarchy is carried by numbering and indentation, blocks are separated by blank lines, and a source URL is written last on its line so nothing is dragged into the link DingTalk draws round it. `--format json` gives the same payload for anything that parses rather than reads it.

Send it as a text message, never as a Markdown one: DingTalk parses a Markdown message before rendering, and that parse turns every single newline into a space, so a three-line title arrives on one line and a paragraph ending in a URL swallows the break after it. `dws chat +messages-send --identity user --open-dingtalk-id <id> --msg-type text --text "$(cat message.txt)" -y` is the channel that keeps the message byte for byte; `dws chat +dm` looks equivalent but defaults to Markdown. A DingTalk text message holds 5120 characters, which is why the 3000-character default leaves room to spare — and why a page already printed under a channel is not printed again in 来源检查, and an offer's row names its band without repeating the model's window, so less has to be summarized away.

Comparison and scan share one shape: what the model is for first, the conclusion next, the detail after that, the summary of what differs last. Forward that structure — keep the title, the model introduction, the one-line conclusion, the per-channel model counts and amounts, and the detail for the channels that moved — and condense only the words, never the structure or a number. A reader who sees only the message should learn what the model does, which channel moved, and what it did without opening anything else or asking a follow-up, and be able to check any amount against the page it came from.

Before any `--refresh` source request, the script fetches the skill repository's configured Git upstream. It fast-forwards and restarts with the updated skill only when the upstream changed this skill, the branch can fast-forward, and the working tree is clean. It otherwise continues with the current code and reports `skill_update` as `up_to_date`, `update_skipped`, or `check_failed`; never hide that status. If an overseas source is unreachable and no fresh cache exists, report `source_error` and say its price is unknown.

Use family matching for availability comparisons; use `--exact` only for an exact official ID. Never merge self-deployed, platform-hosted, third-party-hosted, upstream-direct, first-party, Batch, cache, context, service-tier, time-band, promotion, version, currency, or region variants.

Model identity ignores documentation footnote markers (`deepseek-flash(1)` == `deepseek-flash`). Officially retired names are mapped to their live model, so `deepseek-v4-flash` resolves to `deepseek-flash`; always report the `model_id` actually returned. A vendor that files the live model under its own spelling is also matched (`deepseek-v4.1-flash` and `deepseek-v4-1-flash` are the same model, so one query reaches every platform serving it), but that link is one-way: a live model never absorbs the price rows of a superseded generation. `--exact` insists on the literal official id either way. A model that is listed but priced per second, per request, or only on a free tier produces no price rows — say so rather than reporting a price of zero.

Table-driven adapters keep cache-hit and cache-miss prices apart (`输入（未命中缓存）` is regular input pricing, not cached-input pricing), and ignore headers that bill a non-token unit such as audio duration. A header that describes the request rather than a price — a length band like `条件 输入长度：千 token`, or a peak/off-peak label — is a condition, never a price column; reading one as a price silently drops the tier or time band that distinguishes rows. They read only amounts that name their own currency, so a page publishing both CNY and USD tables yields the CNY catalogue. Never relabel one currency as another.

Peak and off-peak hours are set per platform and must never be carried across them. For `deepseek-flash`: DeepSeek's own page, Ark, and Tencent's 原厂直供 series all peak on weekdays 9:00–12:00、14:00–18:00 with everything else — the whole weekend included — off-peak, while Aliyun's model-market detail page says “错峰时段指东八区22点至次日8点，此外为忙时”. The two calendars therefore agree only on weekday mornings/afternoons and late at night; at midday, in the evening, and all weekend Aliyun is the odd one out and costs double. Each window is read from that vendor's own document into `time_bands`, quoted as the vendor wrote it, and printed once per channel under 峰谷时段; a peak/off-peak row names its own band and nothing more, because every offer of one model publishes the same hours. A platform that publishes no window stays empty — never give it another platform's hours. One page can bill two generations on different calendars (Tencent's 0731/0813 self-hosted builds keep peak at weekends, unlike the 原厂直供 series on the same page), so a rule is selected by model name first and by delivery label (原厂直供) second.

Prefer a representation the official page publishes for machines over scraping its rendered markup: the page's own Markdown copy when it publishes one with real Markdown tables, otherwise its public structured JSON. Parse rendered HTML only when the vendor publishes neither. Never ask for or store credentials. The only authenticated-console exception is refreshing the explicit Tencent model-description mirror through a user-owned logged-in session; do not copy account, billing, key, or other private console data into it.

Code layout: `scripts/query_model_prices.py` is the stable CLI entry point; the implementation lives in `scripts/model_price/`, with one price module per vendor under `providers/`, the independent model-introduction package under `descriptions/`, and shared concerns split into `core` (HTTP + source contract), `parsing` (document readers), `pricing` (record shapes), `models` (identity), `caching`, `updating`, `snapshots` (the baselines `delta` compares against), `diffing` (what moved between two baselines), `delta` (the scan-and-compare run), `reporting` (the shared wording and value formatters), `messages` (the two plain-text messages those values are laid into), `budget` (how far a message overruns the character limit it has to fit), and `registry` (wiring). Add a price provider by writing its module and listing it in `providers/__init__.py`; an adapter that parses its document in one pass overrides `catalog_records()` so a whole-catalogue scan costs one read instead of one query per model. Add introduction sources through `descriptions/sources.py` and keep their provider selection in `descriptions/resolver.py`.
